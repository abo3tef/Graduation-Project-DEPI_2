## Architecture and behavior

- Route-level code is in the locale-aware Next.js `app` route; feature behavior resides in `features/medical-timeline`.
- API requests use the established native-fetch shared client and TanStack Query. Wire responses are narrowed at the API boundary.
- `useActingIdentity` supplies the existing actor identity used for medical-data cache separation. The development token store exposes only a monotonic revision to query keys; raw tokens are never query-key values.
- Backend authorization remains authoritative. UI state and identity-scoped caches are not represented as substitutes for backend access checks.
- F8 patient picker integration remains deferred; the delivered temporary selector accepts a patient GUID.
