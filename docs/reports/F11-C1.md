## Delivered behavior

- `GET /api/admin/users` returns a Q-04 paged envelope over Doctor, Secretary and Admin accounts.
  Role/status filters, a 100-character search (exact GUID or full name/email/phone contains),
  data-source count/order/page, ordinal email + GUID ordering and `400` on invalid input are all
  implemented. Page size is capped at 50.
- `PATCH /api/admin/users/{id}/status` activates/deactivates any account, blocks self-deactivation,
  protects the last active Admin, tolerates a no-op and returns a credential-free representation.
- `PUT /api/admin/users/{id}/role` performs a Doctor↔Secretary table move with the same GUID,
  credentials, status, verification state and original `CreatedAtUtc`. Unconsumed one-time tokens
  follow the new account kind. Conflicting data returns `409 admin.role_change_blocked` before any
  write; Admin targets, self-changes and an `Admin` request role are rejected.
- `GET`/`PUT /api/admin/secretaries/{secretaryId}/doctors` read/replace Q-16 assignments. The set is
  bounded to 100 unique non-empty GUIDs, unknown doctors are `404`, and the join key enforces unique
  pairs at the database boundary. Replacing assignments immediately changes the secretary's
  patient and appointment scope.
- All routes are protected by the controller's Admin policy and by a service-side active-Admin
  check. A deactivated account cannot log in; an already-issued JWT is not revoked but cannot be
  used to administer after the Admin account is deactivated.
- No response contains a password, hash, access token or one-time token value.

### Failures found and fixed during implementation

1. EF Core rejected `UNION` after a DTO projection. The service now unions a simple server-side
   projection and maps to `AdminUserRecord` last; filtering/counting stay in the data source.
2. `CreatedAtUtc` was overwritten on the table move by the shared audit hook. The first workaround
   used an unfiltered relational `ExecuteUpdateAsync`, which would have rewritten **every**
   doctor/secretary timestamp — a real defect found in review. Replaced with the audit-hook fix and
   the workaround removed.
3. The in-memory provider treats transaction warnings as errors, and one HTTP test used a
   placeholder password hash. Tests now use a real PBKDF2 test hash where login is exercised, and a
   real transaction is opened only on relational providers.
4. The Secretary→Doctor conflict check looked for doctors assigned to an id equal to the
   secretary's id instead of that secretary's own assignments. Fixed with a focused regression test.

## Deviations and remaining risks

1. `Medilog.Infrastructure.Persistence.AccountAdmin` is used as the implementation namespace because
   `Admin` would shadow the domain entity name.
2. The list/status endpoints include Admin accounts even though the role-change endpoint does not
   accept `Admin`; this is required to make the last-Admin protection inspectable.
3. The shared audit hook now preserves an explicitly supplied `CreatedAtUtc`. This is a small cross-
   feature behavior change, but the full 770-test suite is green and it is required for identity
   continuity during a role move.
4. Q-16 and Q-22 were implemented using the defaults already recorded as proposals in `STATE.md`;
   their formal approval must still be recorded by the Tech Lead.
5. Changes are uncommitted on `main`; no branch, commit or push was created.
