# Execution Report — F1-C2

- **Date / Contributor / AI tool used:** 2026-11-12 / Menna / Claude Code
- **Branch:** `feature/menna-appointments` (original repository, not `menna-workspace`)
- **Goal:** Application-layer appointment use cases (book, reschedule, cancel, update status, get, list) enforcing secretary↔doctor scope, overlap prevention, past-date rejection, legacy-row handling, concurrency protection, and FluentValidation.

## Delivered
- `IAppointmentService` / `AppointmentService` with six use cases; the acting user always comes from `ICurrentUser`.
- Scope: doctors see/act only on their own appointments; secretaries only on doctors assigned through `doctor_secretaries`; out-of-scope ids behave exactly like missing ones (404 semantics).
- Overlap: candidate rows come from the database (same doctor, same date, status not Cancelled/No-Show, optionally excluding itself); the rule is evaluated by the Domain method `OverlapsInterval`. Legacy rows with `end_time = NULL` are treated as a point at their start time with a warning log.
- Clinic time: `ClinicClock` reads `Clinic:TimeZone` (`Africa/Cairo`); invalid/missing zone throws a clear error (no UTC fallback); non-existent (DST-gap) local times are rejected.
- Concurrency: every write runs in a transaction whose first statement locks the doctor row (`SELECT … FOR UPDATE`); the appointment is re-read inside the lock.
- Roles for status changes: Completed = doctor only; Confirmed and No-Show = doctor or assigned secretary.
- Validators for every request and the list query; typed exceptions (`NotFoundException`, `ForbiddenException`, `ConflictException`, `RequestValidationException`); temporary `PagedResult<T>`.
- Persistence port `IAppointmentStore` (Application) implemented in Infrastructure; reads project straight to `AppointmentResponse` (administrative columns only).
- xUnit project `Medilog.Application.Tests` added to the solution.
