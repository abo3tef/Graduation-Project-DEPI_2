## 1. Trigger

The merge brought two independent frontend API layers into the same tree:

- **F1 (appointments):** `lib/api/client.ts` (`apiRequest`, `getAuthBaseUrl`), `lib/api/errors.ts`
  (`ApiError` with `code`/`fieldErrors`/`errorCodes`/`traceId`), and an `auth-headers` provider for
  the temporary `X-User-Id` / `X-User-Role` headers.
- **F4 (medical records):** `lib/api/api-client.ts` (`request`/`requestVoid`), `lib/api/env.ts`
  (`apiBaseUrl`), `lib/api/problem-details.ts`, and a second `ApiError` class with status-based
  `kind`, plus an explicit per-request `Authorization: Bearer <token>` argument.

Both reached `fetch` directly, defined their own base URL and their own error type. `index.ts`
exported F1's `errors.ts` but F4 code imported `ApiError` from `@/lib/api` and used F4's `kind`
values, so `instanceof ApiError` and `kind` were semantically inconsistent.

## 2. What changed

### One transport

- `lib/api/client.ts` is now the only module that calls `fetch`. It keeps `apiRequest` and adds
  `apiRequestVoid`; `index.ts` exports the same functions under the names F4 already used
  (`request` / `requestVoid`). Options gained an optional `token` so a caller that holds a bearer
  credential can still pass it explicitly.
- Aborted requests are rethrown unchanged (checked via the signal and `AbortError`), so React Query
  keeps treating cancellation as a normal lifecycle event.
- Requests use `cache: 'no-store'` and `credentials: 'omit'` (authentication is header-based).

### One error model

- `lib/api/errors.ts` is the single `ApiError`. It keeps F1's rich fields (`code`, `title`,
  `detail`, `fieldErrors`, `fieldErrorCodes`, `traceId`) and adopts F4's status-derived `kind`:
  `network | invalid-response | unauthorized | forbidden | not-found | conflict | validation | server`.
- `parseProblem` derives `kind` from the status via the new `kindFromStatus`. `createNetworkError`
  and `createInvalidResponseError` keep their dedicated kinds.

### One identity surface

- `lib/api/auth-headers.ts` is now a registry (`registerAuthHeadersProvider` returns an unregister
  function; `resetAuthHeadersProviders` clears it for tests). `getAuthHeaders` merges every
  provider on each request.
- The appointments dev identity (`features/auth/dev-identity`) registers its `X-User-*` provider;
  the medical-records dev token (`features/medical-records/use-dev-token`) registers an
  `Authorization: Bearer` provider. Both now flow through the same transport and the same registry,
  so there is one place where "who is calling" is attached.

### Removed

- `lib/api/api-client.ts`, `lib/api/env.ts`, `lib/api/problem-details.ts` (no remaining importers).
- The duplicate `ApiError` class and `toErrorKind`/`send`/`readProblem` helpers.

### Consumer updates

- `features/medical-records/guards.ts`: `new ApiError(0, 'server', null)` → `createInvalidResponseError(0)`.
- `features/medical-records/hooks/use-medical-visit.ts`: positional `ApiError` → init object.
- Tests updated to the registry names and the unified `kind` (`'http'` → the status kind, e.g.
  `'conflict'`).

No business rule, endpoint, route, or user-facing text changed. F1 and F4 keep their observable
behaviour; the change is structural.

## 4. Deviations / notes

- The two development identity mechanisms still represent two different auth models (headers vs.
  bearer JWT). They are unified at the *attachment surface* (one transport, one registry), not
  collapsed into one credential. Removing the explicit `token` argument from the medical-records
  call chain was deliberately avoided: it has no unit tests and is already a working integration,
  so the refactor keeps that behaviour intact and adds the shared provider on top.
- `kind` semantics changed from F1's transport-level `'http'` to status-derived values. This is the
  intended merge of the two models; the F1 consumers that switch on `network` /
  `invalid-response` are unaffected, and the rest already fell back to status/code.
- Validation-error casing debt from P0-C2 is unchanged (F1 camelCase + `errorCodes`, F4
  PascalCase). It remains P1-C1 work.
