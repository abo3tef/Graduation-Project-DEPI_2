## API contract (all routes require role **Doctor** or **Secretary**)

| Method | Route | Success | Notes |
|---|---|---|---|
| `POST` | `/api/payments` | `201` + `Location: /api/payments/{id}` | Creates `Pending`; body `{appointmentId, amount, method, notes}` |
| `GET` | `/api/payments` | `200` `PagedResult<PaymentResponse>` | `search, status, method, patientId, appointmentId, doctorId, dateFrom, dateTo, pageNumber, pageSize` |
| `GET` | `/api/payments/{id}` | `200` `PaymentResponse` | Out-of-scope ids are indistinguishable from missing (`404`) |
| `PUT` | `/api/payments/{id}` | `200` `PaymentResponse` | Amount/method/notes only; `409` when already `Paid` |
| `PUT` | `/api/payments/{id}/status` | `200` `PaymentResponse` | `{status}`; invalid transition `409` |
| `GET` | `/api/payments/payable-appointments` | `200` list | `search` + bounded `limit` (default 50, max 100); excludes Cancelled/No-Show and already-billed appointments |

Authorization outcomes: anonymous → `401`; any other role (e.g. `Admin`) → `403`; unknown/inactive actor → `403 identity.invalid`.

`PaymentResponse`: `{id, patientId, patientName, doctorId, appointmentId, appointmentDate, amount, method, status, paidAt, notes}` — no medical data, no `createdBy`/`createdAt`.

Error codes: `400 validation.failed` (and domain shape codes), `403 identity.invalid`, `404 payment.not_found` / `payment.appointment_not_found`, `409 payment.already_exists` / `payment.invalid_status_transition` / `payment.paid_final`.

## Payment model as implemented (basis for the Q-21 record)

- One payment per appointment; `appointment_id` unique. Partial collection = the single row's `Partial` status.
- `patient_id` and `doctor_id` are copied from the appointment; revenue is attributed to `doctor_id`.
- Money: `decimal(18,2)`, `0 < amount <= 1_000_000` (matches F2 `PAYMENT_AMOUNT_MIN/MAX`).
- Methods `Cash|Card`; statuses `Pending|Partial|Paid`; `paid_at_utc` is set only when the row reaches `Paid`.
- Transitions: `Pending→Partial`, `Pending→Paid`, `Partial→Paid`; `Paid` is final; everything else is `409 payment.invalid_status_transition`.
- Writes: doctor on own payments; secretary on payments of assigned doctors (existing `doctor_secretaries` scope). A client-supplied `doctorId` can only narrow the visible scope.
- Revenue definition (recorded, **not implemented** here): `SUM(amount) WHERE status = 'Paid' AND doctor_id = @doctorId`.

## Decisions confirmed by the Tech Lead (2026-11-15)

1. **POST creates `Pending` — confirmed.** The request has no `status`; reaching `Paid` requires `POST` then `PUT /{id}/status`. F7-C2 adapts the F2 screen, whose mock currently creates `'paid'`.
2. **Paid payments are immutable — confirmed** (`409 payment.paid_final`).
3. **`paidAt` is nullable — confirmed.** F2 type becomes `string | null` in F7-C2.
4. **Payable picker eligibility — confirmed and implemented.** `GET /api/payments/payable-appointments` now excludes `Cancelled` and `NoShow` appointments as well as already-billed ones; `Scheduled`, `Confirmed` and `Completed` unbilled appointments remain payable. Covered by a 5-status Application theory and an API test.
5. **`[Authorize]` stays — confirmed.** Normal Development runs use `dotnet user-jwts` tokens until F6-C1 merges.
6. **Dashboard stays out of scope — confirmed.** `totalRevenue` remains `null`.

### Residual notes (not blocking)

- A direct `POST /api/payments` for a `Cancelled`/`NoShow` appointment is still accepted; only the picker excludes those statuses. Blocking them at create time was not requested and is not implemented.
- `dateFrom`/`dateTo` filter the billed appointment date (the date F2 displays), not `created_at_utc`.
- **`[Authorize]` is present now**, before F6-C1 merge; normal Development runs only authenticate `dotnet user-jwts` tokens, while tests use `WebApiFactory`/`TestAuthHandler`.
- **Error-code ownership:** the global uniqueness test rejected duplicated `payment.*` codes, so `payment.invalid_status_transition` and `payment.paid_final` live only in `DomainErrorCodes` and are referenced by the service/tests.

### Appointment → Payment (one-to-one)

`payments.appointment_id` is `NOT NULL` and has the unique index
`ux_payments_appointment_id`, so an appointment can be billed at most once.
`patient_id` and `doctor_id` are copied from the appointment when the payment is

or doctor cannot be deleted while the payment exists. Partial collection is the
`Partial` status of the single row, not extra rows.
