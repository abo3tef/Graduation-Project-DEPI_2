## Contract, validation and security

- API functions match C1's POST/GET/PUT paths. Existing native-fetch client, ApiError, PagedResult and readPagedResult are reused.
- Response contains id plus seven nullable measurements. Save bodies pick only those measurements, excluding ownership and route IDs. Validated blank fields become explicit nulls; PUT replaces all seven.
- The frontend guard now requires and validates vitalSigns on visit detail responses. C1 must be deployed first; an older backend omitting this property is not supported by the new reader.
- Temporary Q-19 rules remain **Pending Tech Lead Approval**: BP systolic/diastolic, maximum 20 chars, systolic 50–300, diastolic 20–200, systolic > diastolic; HR 20–300; temperature 30–45 Celsius; respiratory rate 4–80; SpO2 50–100%; weight 0.3–500 kg; height 20–260 cm. All fields optional individually; all-empty submissions rejected. Integer fields mirror backend integers.
- Queries use opaque credential generations; no raw bearer tokens or token representations enter query keys. Generation advances on existing token save/clear events, not React rendering. Both list and detail queries use the strategy.
- Existing visit mutations capture their originating scope and suppress stale cache writes. Vitals mutations invalidate visit/list prefixes without seeding response data into another scope. Token removal hides the section; an open form hides on credential change.
- Backend remains the authorization boundary. No JWT parsing, development-role ownership assumption or new role guard was introduced. The host exposes no vitals write controls while trusted doctor/owner authorization is unavailable.
- Display follows server Id ordering without claiming latest/most recent. No timestamp was added. This read-only presentation was explicitly authorized despite the older task's latest/history wording.
