### P0-C2 — Backend foundation unification

- **One identity abstraction:** `Medilog.Application.Common.Abstractions.ICurrentUser` with
  `Guid? UserId` and `UserRole? Role`; `Medilog.Application.Interfaces.ICurrentUser` deleted.
- **One implementation:** `Medilog.WebAPI.Common.CurrentUser` reads the JWT claims
  (`ClaimTypes.NameIdentifier`/`sub`, `ClaimTypes.Role`/`role`) and, only when
  `Auth:AllowHeaderIdentity=true`, falls back to `X-User-Id`/`X-User-Role`.
  `Medilog.WebAPI.Security.HeaderCurrentUser` deleted. User ids use the hyphenated ("D") form.
- **Authentication wired:** `AddAuthentication(JwtBearerDefaults.AuthenticationScheme).AddJwtBearer()`
  and `AddAuthorization()` are registered, so `[Authorize(Roles = "Doctor")]` now has a principal.
  `UseAuthentication()` runs before `UseAuthorization()`.
- **One error handler:** `Medilog.WebAPI.Common.GlobalExceptionHandler` merges the F1 and F4
  handlers. It maps `RequestValidationException`, FluentValidation `ValidationException`,
  `NotFoundException`, `ForbiddenException`, `ConflictException`, `DomainException`, and unexpected
  failures, and always emits `code` + `traceId`. `Medilog.WebAPI.Middleware.ApiExceptionHandler`
  deleted.
- **One exception family:** `AppException.cs` is the only definition of
  `NotFoundException`/`ForbiddenException`/`ConflictException`; the message-only duplicates from the
  merge were deleted. Constructors accept an optional code, defaulting to new generic codes
  (`resource.not_found`, `access.forbidden`, `resource.conflict`).
- **Consumers updated:** `AppointmentService` and `MedicalVisitService` use the nullable identity
  with explicit actor guards; test fakes/fixtures updated to the unified interface.
- Removed duplicate `AddApplication()` / `AddInfrastructure()` registrations and duplicate exception
  handler registrations; added the missing `Microsoft.Extensions.DependencyInjection` using in
  `Application/DependencyInjection.cs`.

## 4. Deviations / notes

- The two branches validated validation errors differently: F1 camel-cases field keys and adds
  `errorCodes`; F4 keeps FluentValidation's PascalCase property names. Both observable behaviours
  were preserved so the approved tests stay green. Unifying this casing is FS work for P1-C1 and is
  recorded as debt, not changed here.
- `IAppointmentStore` (F1) and `IApplicationDbContext` (F4) both remain. They serve different
  purposes (transactional `FOR UPDATE` port vs. EF query surface); merging them is a separate,
  riskier refactor.
- No database, migration, or business-rule change was made. The MySQL round-trip is still
  unverified because no local instance is available.
