## API and security contract

- `POST /api/medical-visits/{visitId}/vital-signs`: 201, measurement response; Location points to the visit's vitals list.
- `GET /api/medical-visits/{visitId}/vital-signs`: 200, shared `PagedResult<VisitVitalSignsResponse>`; pageNumber/pageSize, default size 10, maximum 50; stable Id order, not chronology.
- `PUT /api/medical-visits/{visitId}/vital-signs/{vitalSignsId}`: 200; full replacement of all seven measurements. Explicit null clears the old value.
- Save request has only bloodPressure, heartRate, temperature, respiratoryRate, weight, height, spO2. Route visit determines the patient. Ownership IDs are not input properties.
- Doctor role is enforced on the controller and in the service. Queries enforce visit ownership; PUT additionally matches measurement ID and route visit ID. Other doctors receive scoped 404; secretary receives 403; unauthenticated HTTP requests receive 401. Validation failures use the existing 400 error envelope.
- Application code uses IApplicationDbContext, ICurrentUser, existing exceptions and CancellationToken. No MediatR, extra repository, package, authentication or migration changes.
- Existing identity assumes ICurrentUser.UserId is the doctor profile ID. This must be verified against F6's final claims contract.
