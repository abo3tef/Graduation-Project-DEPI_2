# Execution Report — F1-C4 (with F1-C3b)

- **Date / Contributor / AI tool used:** 2026-11-13 / Menna / Claude Code
- **Branch:** `feature/menna-appointments` (original repository, not `menna-workspace`)
- **Goal:** Secretary appointment & booking screens in Next.js (Arabic RTL / English LTR) on top of the F1-C3 API, preceded by the backend mini-cycle F1-C3b (lookups, machine-readable error codes, synthetic dev seed).

## Delivered

**F1-C3b (backend)**
- `GET /api/appointments/lookups/doctors` (self, or a secretary's assigned **active** doctors) and `GET /api/appointments/lookups/patients?doctorId&search&limit` (that doctor's patients only; 404 if out of scope; `limit` 1–20 applied in the database; literal text matching). Responses: `id`, name, phone (doctors: specialization) — no medical data.
- Stable `code` on every application problem response, per-field `errorCodes` on validation failures, `DomainException` with domain codes; code table in `backend/docs/api/appointments.md`.
- `backend/docs/dev/seed-dev-data.sql` (4 doctors incl. one unassigned and one inactive, a secretary with assignments, 6 patients, 5 appointments; idempotent; cleanup section).

**F1-C4 (frontend)**
- Routes `/{ar|en}/appointments` (list, filters, pagination, row actions) and `/{ar|en}/appointments/new` (booking), feature-local app bar, localized page titles.
- List: filters by doctor / status / date range (default: today onward in the clinic time zone), server-side paging (10), loading / empty / error (with retry) / no-identity states, table from `md` up and cards below, row actions by status × role (Complete only for a Doctor).
- Booking: doctor select (single doctor pre-selected), ARIA combobox patient search (needs a doctor, ≥ 2 characters, debounced, keyboard operable), date, start/end (both required; quick 15/30/45/60 buttons only fill the end when pressed — no default duration), reason (≤ 1000, counter), the doctor's day schedule with a **hint** for overlaps using the server's rule.
- Dialogs on native `<dialog>`: reschedule (date/time only), cancel (mandatory reason ≤ 500, counter), status (Confirm / No-show / Complete with confirmation).
- `src/lib/api`: fetch client, one `ApiError`, single auth-headers provider; the temporary dev identity (`X-User-Id`/`X-User-Role`) is registered from `features/auth/dev-identity`, active only when `NEXT_PUBLIC_DEV_IDENTITY=true` in a non-production build.
- Errors are shown from the API `code` (then the HTTP status) as translated text; the server's English text is never displayed.
- `Appointments` (141 keys) and `DevIdentity` (13 keys) namespaces in `ar.json` and `en.json`, identical keys; logical Tailwind utilities only; times in `<bdi>`, phones `dir="ltr"`.
- Vitest + Testing Library + jsdom with `npm test`; `frontend/.env.example`; README section on running against the API.

## Deviations from plan (all approved)
1. Vitest **4.1.12** instead of the latest 5.x (peer conflict with the repo's `@types/node ^20`); dev dependencies added: `vitest`, `jsdom`, `@testing-library/{react,dom,user-event,jest-dom}`.
2. `DevIdentity` is its own message namespace; Zustand is not used for the identity (a `useSyncExternalStore` module is hydration-safe).
3. Both screens render behind `<Suspense>` with a static fallback because Next `cacheComponents` rejects reading the current time while prerendering.
4. Detail page (`/appointments/[id]`) intentionally not built (Q-C4-07).
