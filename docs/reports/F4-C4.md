# Execution Report — F4-C4 (Medical entry/edit screens)

- **Date / Contributor / AI tool used:** 2026-11-11 → 2026-11-12 / Mohamed Shalaby (Member 4) / OpenCode
- **Branch:** `feature/shalaby-visits`
- **Cycle:** F4-C4 — the frontend slice of F4. Plan approved 2026-11-11
  (`docs/tasks/F4/F4-C4.md`, decisions D-27…D-31, Q-11 deferred). Delivered in three increments:
  C4a (API client, token bridge, workspace), C4b (visit create/detail/inline edit),
  C4c (diagnoses, medications, permanent-delete confirmation).
- **Goal:** let a doctor record a visit, add/edit its diagnoses and add/edit/delete its medication
  lines from the frontend, against the frozen `MEDICAL_RECORDS_API.md` contract, with no new
  dependency and no backend change.

## Delivered

### C4a — HTTP layer, token bridge, workspace (`5f6eb85`)

- `src/lib/api`: `env.ts` (`NEXT_PUBLIC_API_BASE_URL`, dev default `http://localhost:5208`),
  `problem-details.ts` (RFC 7807 shape + `toFieldErrors`), `api-client.ts` (`request`/`requestVoid`,
  normalised `ApiError` with `kind` + `fieldErrors`, `204`/JSON handling, abort pass-through).
- Feature module `src/features/medical-records`: `types.ts`, `guards.ts` (hand-written narrowing,
  no schema library), `api.ts` (the eight documented calls), `keys.ts`, `validation.ts`,
  `use-dev-token.ts` (sessionStorage + `useSyncExternalStore`, SSR-safe, no token echo).
- Routes: `/[locale]/medical-records` layout + workspace ("open by id", GUID-checked) with
  `DevTokenPanel`.
- i18n: `MedicalRecords` namespace in `en.json`/`ar.json`; `--danger` theme token.

### C4b — Visit create, detail and inline edit (`8312d64`)

- Routes: `/[locale]/medical-records/visits/new` (`?patientId=` seed) and
  `/[locale]/medical-records/visits/[visitId]`.
- `AsyncState` (`LoadingPanel`/`StatePanel`), `FormField` (render-prop a11y wiring), `VisitForm`
  (create + edit), `VisitDetails` (read-only summary + inline edit), `NewVisitScreen`,
  `MedicalVisitScreen` (`401/403/404/network/server` states, malformed-id short-circuit, token gate).
- `errors.ts` (`QueryFailureKind`/`MutationFailureKind`, `fieldErrorsOf`), `use-medical-visit.ts`,
  `use-visit-mutations.ts` (create seeds the detail cache, update writes the returned visit).
- `Header` link to the workspace; visit field limits and GUID/date rules in `validation.ts`.

### C4c — Diagnoses, medications, delete confirmation

- `validation.ts`: `DIAGNOSIS_FIELD_LIMITS` (200/4000), `MEDICATION_FIELD_LIMITS` (200/100/100/100/4000,
  D-26), `validateDiagnosisForm`, `validateMedicationForm`, `toDateOnlyValue`, `parseDateOnlyUtc`,
  `todayDateOnly`, `latestDiagnosisDateOnly` (exactly `DateOnly.FromDateTime(DateTime.UtcNow).AddDays(1)`).
- `use-diagnosis-mutations.ts` (create/update), `use-medication-mutations.ts` (create/update/delete).
  Every success invalidates `medicalRecordKeys.visit(visitId)`, so the refetched
  `MedicalVisitResponse` stays the single source of truth for both lists (D-24). Delete has no
  optimistic removal (D-23).
- `DiagnosisSection`/`DiagnosisForm`, `MedicationSection`/`MedicationForm`,
  `ConfirmDeleteDialog`, `MutationAlert`, `form-styles.ts`. `VisitForm` was refactored onto the
  shared styles/banner with unchanged behaviour.
- `ConfirmDeleteDialog`: `role="dialog"` + `aria-modal`, labelled/described, focus starts on the
  safe action, `Tab` trap, `Esc` ignored while pending, body scroll lock, focus restored to the
  trigger (or `#medications-add` when the trigger row is gone), explicit "cannot be undone" copy.
- `MedicalRecords.diagnosis`, `.medication`, new `validation`/`notifications` keys and
  `common.validationSummary` in both message files (229/229 keys, no orphans).

## Deviations from the plan

| # | Deviation | Reason |
|---|---|---|
| 1 | `guards.ts`, `validation.ts`, `errors.ts`, `MutationAlert.tsx`, `form-styles.ts` are extra files relative to the plan's file list | All inside the approved scope: they keep response narrowing, rules and form styling in one place instead of duplicating them per form |
| 2 | A `deleteMutation.isSuccess` effect in `MedicationSection` moves focus to `#medications-add` | The dialog's own focus restore could not use the deleted row (it unmounts after the refetch), so focus would otherwise fall to `<body>` |
| 3 | Manual `<Suspense>` boundary reveal during verification | The verification browser never services `requestAnimationFrame`, so Next.js streamed boundaries never self-reveal there; a harness limitation, not an app defect |
