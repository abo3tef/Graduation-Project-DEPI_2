# F11-C1 — Admin Dashboard: Backend

- Feature: F11 — Admin Dashboard & Full E2E Integration   - Owner: Abdullah   - Branch: `feature/abdullah-admin-integration`   - Phase: Phase 2
- Status: Approved
- Depends on: F6-C1 (identity model + login for Admin)

## Goal
Admin endpoints to list, activate/deactivate, and manage the role of doctor and secretary accounts, and to assign secretaries to doctors.

## Source requirements
FR-42 (secretary account management and assignment), SRS §5.2 (Admin role), BR-19; BRULE-01, BRULE-10; role editing is a Phase 2 team item with rule Q-22.

## Business rules & security constraints
Admin role only (`[Authorize(Roles = "Admin")]` + service check); Admin cannot deactivate or change the role of their own account; the last active Admin is protected; a deactivated account cannot log in (F6 rule; already-issued tokens stay valid until expiry — document this); role changes follow Q-22; assignments use `SecretaryDoctor` with unique pairs (Q-16); no passwords or tokens in responses; all inputs validated.

## Affected layers & files
Application: admin account service, DTOs, validators, mapping profile. Infrastructure: queries/indexes for filtering. Api: `AdminController`.

## API contract (proposed)
`GET /api/admin/users` (filters: role, status, search; pagination) · `PATCH /api/admin/users/{id}/status` (active/inactive) · `PUT /api/admin/users/{id}/role` · `GET/PUT /api/admin/secretaries/{secretaryId}/doctors` (assignments, Q-16).
