## 1. Goal

Expose the F1-C2 use cases over HTTP, safely and consistently:

1. `AppointmentsController` with Book, Reschedule, Cancel, UpdateStatus, GetById and List (filtering + pagination).
2. Role protection with `[Authorize(Roles = …)]` for Doctor and Secretary only; no medical data in any response.
3. `ICurrentUser` implemented from the authenticated `HttpContext` claims; `IAppointmentService` registered in DI.
4. One global exception → HTTP mapping (NotFound 404, Forbidden 403, Conflict 409, `DomainException` / `RequestValidationException` 400).
5. Automated tests of the HTTP layer; `dotnet build` and `dotnet test` green.

**Out of scope:** login/token issuance, password hashing, user provisioning (Q-07 — Authentication work), the frontend (F1-C4+), payments, any medical endpoint, schema changes.

## 4. Proposed design

### 4.1 Endpoints (proposal; routes need approval, Q-C3-02)

All under `[ApiController]`, `[Route("api/appointments")]`, `[Authorize(Roles = "Doctor,Secretary")]`.

| Verb + route | Use case | Success | Failures |
|---|---|---|---|
| `POST /api/appointments` | Book | **201** + `Location` → GetById, body `AppointmentResponse` | 400, 401, 403, 404 (doctor/patient not in scope), 409 (overlap, inactive doctor) |
| `GET /api/appointments/{id}` | Get | 200 `AppointmentResponse` | 401, 403, 404 |
| `GET /api/appointments?doctorId&patientId&dateFrom&dateTo&status&pageNumber&pageSize` | List | 200 `PagedResult<AppointmentResponse>` | 400 (bad paging/filter), 401, 403 |
| `PUT /api/appointments/{id}/schedule` | Reschedule (date, start, end only) | 200 updated appointment | 400, 401, 403, 404, 409 |
| `POST /api/appointments/{id}/cancel` | Cancel (mandatory reason) | 200 updated appointment | 400, 401, 403, 404 |
| `PUT /api/appointments/{id}/status` | Confirm / Complete / No-Show | 200 updated appointment | 400, 401, 403 (secretary completing), 404 |

Notes:
- Cancel returns the updated resource (not 204) so the UI refreshes without a second call.
- Bodies are the existing Application request records; the controller never sets creator/role/status itself.
- `CancellationToken` comes from `HttpContext.RequestAborted`.
- `[ProducesResponseType]` on every action so OpenAPI documents the contract.
- Controller methods are one-liners over `IAppointmentService`.

### 4.2 Authentication boundary and `ICurrentUser` (blocking question Q-C3-01)

**Proposal — provider-agnostic claims contract:**
- `HttpContextCurrentUser : ICurrentUser` (WebAPI, scoped) reads `IHttpContextAccessor.HttpContext.User`:
  - `UserId` ← claim `NameIdentifier` (or `sub`), parsed as `Guid`;
  - `Role` ← the role claim, mapped case-sensitively to `Doctor` / `Secretary`.
- **Fail closed:** missing/invalid id → `Guid.Empty`; missing/unknown role → an undefined `UserRole`. The service already rejects both with `ForbiddenException`, and `[Authorize]` rejects unauthenticated callers with 401 first.
- Registered with `AddHttpContextAccessor()` and `AddScoped<ICurrentUser, HttpContextCurrentUser>()`.
- This works with whatever scheme Q-07 chooses, as long as tokens carry those two claims.

**What authentication scheme runs in production?** Not decided (Q-07). Options:
- **(a, recommended)** JWT Bearer *validation* only (issuer/audience/signing key from configuration/user-secrets), with the Auth owner delivering token issuance. This needs the package `Microsoft.AspNetCore.Authentication.JwtBearer` (a new shared dependency → approval required) and `app.UseAuthentication()` before `UseAuthorization()`.
- **(b)** Cookie authentication from the Auth owner.
- **(c)** Defer: ship controllers + claims reader + tests with a *test-only* scheme; production returns 401/500 until Q-07 lands. Not recommended — endpoints would be unusable and untestable manually.

Tests never use production auth: they register a test authentication handler inside the test project.

### 4.3 Exception → HTTP mapping

One `IExceptionHandler` (`ApiExceptionHandler`, WebAPI) registered with `AddExceptionHandler<>()`, plugged into the existing `UseExceptionHandler()` + ProblemDetails:

| Exception | Status | Body |
|---|---|---|
| `NotFoundException` | 404 | ProblemDetails (title, detail = safe message) |
| `ForbiddenException` | 403 | ProblemDetails |
| `ConflictException` | 409 | ProblemDetails |
| `RequestValidationException` | 400 | `ValidationProblemDetails` with `errors` per field |
| `DomainException` | 400 | ProblemDetails (message is domain-safe) |
| Malformed JSON / bad enum / bad date or time | 400 | `[ApiController]` automatic ProblemDetails |
| Unauthenticated | 401 | from the auth scheme |
| `OperationCanceledException` (client aborted) | no body | — |
| Anything else | 500 | generic message only; logged server-side; **no** exception text, stack trace, SQL or ids in the response |

`DomainException` → 400 follows your instruction (note: "cancel an already cancelled appointment" is arguably a 409; if the Tech Lead prefers, a one-line change later).

### 4.4 JSON contract (Q-C3-05)
- Property names camelCase; enums as **strings** via `JsonStringEnumConverter` using the C# names (`Scheduled`, `Confirmed`, `Completed`, `Cancelled`, `NoShow`); dates `yyyy-MM-dd`; times `HH:mm:ss`; timestamps ISO-8601 UTC.
- Unknown enum strings → 400.
- Configured once in `AddControllers().AddJsonOptions(...)`.

### 4.5 Other WebAPI changes
- `Program.cs`: add authentication per Q-C3-01, `UseAuthentication()` before `UseAuthorization()`, `AddExceptionHandler`, `AddHttpContextAccessor`, JSON options, and `public partial class Program { }` so `WebApplicationFactory` can host it.
- `AddApplication()`: register `services.AddScoped<IAppointmentService, AppointmentService>();` (the note left in C2 is removed).
- Startup fail-fast: resolve `IClinicClock` once at startup so a bad `Clinic:TimeZone` stops the app immediately (C2 finding 3).
- Role-name constants in one place (`Roles.Doctor`, `Roles.Secretary`) so attributes and the claims reader cannot drift.
- API contract document `backend/docs/api/appointments.md` (routes, bodies, statuses, error shape, JSON rules) — frontend F1-C4 will depend on it (AGENTS §4.4).

### 4.6 Medical data protection
- The controller returns only `AppointmentResponse` (administrative fields; guarded by the C2 reflection test).
- No route in this cycle touches patients, visits, diagnoses or any medical entity.
- A test asserts that the serialized JSON of every endpoint contains only the whitelisted property names.
- A test asserts a caller whose role is neither Doctor nor Secretary (e.g., Admin) gets 403 on every route.

## 6. Test plan (expected behavior from the rules, not from the code)

**Auth and roles**
- No credentials → 401 on every route.
- Authenticated as Admin/other/unknown role → 403 on every route.
- Doctor and Secretary reach the routes.

**`HttpContextCurrentUser` (unit)**
- Valid GUID + `Doctor` / `Secretary` role claims map correctly.
- Missing id, non-GUID id, missing role, unknown role, wrong-case role → fail closed (service rejects with 403).
- Client-supplied `createdBy`, `role` or `userId` in body, query or headers is ignored (creator equals the claim's id).

**Endpoints**
- Book → 201 with `Location`; body matches; creator = authenticated user; second overlapping booking → 409; adjacent booking → 201.
- Get → 200; out-of-scope id → 404 identical to a missing id.
- List → 200 envelope with `totalCount`, `pageNumber`, `pageSize`, `totalPages`; invalid page/size → 400 with field errors; secretary sees only assigned doctors; status/date/patient filters work.
- Reschedule → 200, status unchanged; conflict → 409; past → 400; end ≤ start / missing end → 400.
- Cancel → 200 with reason stored; blank / 501-char reason → 400; already cancelled → 400.
- UpdateStatus → 200; secretary + Completed → 403; Cancelled via this route → 400; invalid transition → 400.

**Error handling and contract**
- Every mapped exception returns the table in §4.3 with ProblemDetails content type and no stack trace/SQL/internal text.
- An unexpected exception returns a generic 500 body.
- Malformed JSON, unknown enum string, bad date → 400.
- JSON uses string enums and the date/time formats of §4.4.
- Responses contain only the whitelisted property names.

**Wiring**
- The service graph resolves with `ValidateOnBuild` on; an invalid `Clinic:TimeZone` makes startup fail.

**Not verifiable here:** real database behavior, real token issuance, browser CORS from the frontend, end-to-end with MySQL.

## 8. Dependencies, risks, assumptions

- **Blocked by Q-07** for the production authentication scheme (see Q-C3-01).
- **R-1.** Adding an auth package/scheme sets a shared decision other members rely on; it must be agreed first.
- **R-2.** Without MySQL and a token issuer, the API cannot be exercised end to end; confidence comes from HTTP-layer tests with in-memory fakes. C2 finding 1 (real lock) remains open.
- **R-3.** The route and JSON contract becomes the frontend's dependency (F1-C4); changes later need coordination (AGENTS §4.4).
- **R-4.** `DomainException` → 400 for every rule violation loses the 409 nuance for state conflicts.
- **A-1.** Controllers (not Minimal APIs) are used for the new endpoints: `Program.cs` already calls `AddControllers()` and the folder layout expects them (Q-05 formally open).
- **A-2.** CORS, HTTPS redirect and ProblemDetails registrations already in `Program.cs` are kept.
