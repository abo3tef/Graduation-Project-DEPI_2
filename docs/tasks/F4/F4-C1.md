## 1. Goal

Introduce the persisted medical core for F4 — a visit record with its diagnoses and prescribed
medications — as Domain entities plus their EF Core configurations, wired into the existing
`MedilogDbContext` through assembly scanning, compiling cleanly, with **no HTTP surface** in
this Cycle.

Deliberately narrow: this Cycle fixes the persistence contract. Use cases (validators, DTOs,
mapping, endpoints, authorization) arrive in later F4 Cycles.

## 5. Domain model

Conventions preserved from the existing codebase:

- Entities inherit `AuditableEntity` (`backend/src/Medilog.Domain/Common/AuditableEntity.cs`),
  which inherits `BaseEntity` (`Guid Id`, assigned in the property initializer).
- `DateTimeOffset` for timestamps, matching `AuditableEntity`.
- Nullable reference types enabled; **no EF Core attributes in Domain**.
- **No navigation properties** — the entities stay plain data holders (D-02 Option C). All
  relationships, when they exist, are configured in Infrastructure.

### 5.1 `MedicalVisit` — table `MedicalVisits`

| Property | Type | Required | Notes |
|---|---|---|---|
| `PatientId` | `Guid` | yes | BRULE-05. Plain column + index, **no FK** (D-02 Option C) |
| `DoctorId` | `Guid` | yes | BRULE-06. Plain column + index, **no FK** (D-02 Option C) |
| `VisitDateUtc` | `DateTimeOffset` | yes | Stored as UTC |
| `ChiefComplaint` | `string?` | no | max 1000 |
| `ClinicalNotes` | `string?` | no | max 4000; remove if Q-08 excludes clinical notes |

*Not included:* `Status` (Q-03 undefined), `FollowUpDate`, vital signs.

### 5.2 `Diagnosis` — table `Diagnoses` (1 visit → N diagnoses, D-07)

| Property | Type | Required | Notes |
|---|---|---|---|
| `MedicalVisitId` | `Guid` | yes | **Real FK** → `MedicalVisits.Id`, `Restrict` |
| `PatientId` | `Guid` | yes | Plain column + index, **no FK** (D-02 Option C); BRULE-05 |
| `DiagnosisName` | `string` | yes | max 300 |
| `Description` | `string?` | no | max 2000 |
| `DiagnosisDateUtc` | `DateTimeOffset` | yes | Stored as UTC (named `DiagnosisDate` in the Class Spec transcription; renamed per review finding #2) |

### 5.3 `Medication` — table `Medications` (prescribed medication line, D-03)

| Property | Type | Required | Notes |
|---|---|---|---|
| `MedicalVisitId` | `Guid` | yes | **Real FK** → `MedicalVisits.Id`, `Restrict` |
| `PatientId` | `Guid` | yes | Plain column + index, **no FK** (D-02 Option C); BRULE-05 |
| `MedicationName` | `string` | yes | max 200 |
| `Dosage` | `string?` | no | max 100 — free text, e.g. "500 mg" |
| `Frequency` | `string?` | no | max 100 — free text, e.g. "twice daily" |
| `DurationInDays` | `int?` | no | Check constraint `>= 1` when present |
| `Instructions` | `string?` | no | max 500 |

#### Naming note (one-line override available)

The Class Spec transcription lists the field as **`duration`**. This draft uses
`DurationInDays` (`int?`) so the unit is unambiguous and the column is queryable.
If the Class Spec defines free-text duration (for example "5 days"), rename the property to
`Duration` (`string?`, max 50) and drop the check constraint. This does not affect any other
decision in the file.

### 5.4 Consistency invariant to enforce in F4-C2 (not in this Cycle)

`Diagnosis.PatientId` / `Medication.PatientId` and their visit's `PatientId` are independent
columns and can diverge. The application flow in F4-C2 must reject a diagnosis or medication
whose `PatientId` differs from the parent visit's `PatientId`. Recorded here so it is not lost.

### 5.5 Audit columns

All three entities inherit `CreatedAtUtc` and `UpdatedAtUtc` from `AuditableEntity`.

- `CreatedAtUtc` is initialised in each entity's constructor (`DateTimeOffset.UtcNow`), so an
  insert can never persist a default `0001-01-01` value.
- Both columns are configured with `ValueGeneratedNever()`, making it explicit that the store
  never generates these values.
- **F4-C2 must add the audit interceptor** (or set the timestamps explicitly inside the use
  case) before any write path exists. The interceptor becomes authoritative on save and
  maintains `UpdatedAtUtc`. This is a hard dependency of F4-C2, not an optional improvement.

## 6. EF Core configuration plan

New files in `backend/src/Medilog.Infrastructure/Persistence/Configurations/`.
**`MedilogDbContext` is not modified** — configurations are already discovered by
`ApplyConfigurationsFromAssembly` (`Persistence/Context/MedilogDbContext.cs`).

| Configuration | Table | PK | Indexes | Relationships |
|---|---|---|---|---|
| `MedicalVisitConfiguration` | `MedicalVisits` | `Id` | `(DoctorId, VisitDateUtc)`; `(PatientId, VisitDateUtc)` | none configured (D-02 Option C) |
| `DiagnosisConfiguration` | `Diagnoses` | `Id` | `(MedicalVisitId)`; `(PatientId, DiagnosisDateUtc)` | `MedicalVisitId` → `MedicalVisits` `Restrict` |
| `MedicationConfiguration` | `Medications` | `Id` | `(MedicalVisitId)`; `(PatientId)`; `(MedicationName)` | `MedicalVisitId` → `MedicalVisits` `Restrict` |

Rules applied:

- Relationship to `MedicalVisit` is configured with `HasOne<MedicalVisit>().WithMany()`
  and `HasForeignKey(...)` — no navigation properties are added to the entities.
- **`Restrict` everywhere** (`AGENTS.md` §4.3): deleting a visit with children, or a patient
  with history, must never silently cascade.
- All strings use `HasMaxLength`. **No `HasColumnType(...)`** — provider-dependent and D-01 unresolved.
- No decimal columns in this Cycle, so no `HasPrecision` needed.
- `DurationInDays` gets `ToTable(t => t.HasCheckConstraint("CK_Medications_DurationInDays", "[DurationInDays] IS NULL OR [DurationInDays] >= 1"))` **only after the provider is chosen** (the identifier quoting is provider-specific); until then the rule is enforced in the entity/application layer in F4-C2.
