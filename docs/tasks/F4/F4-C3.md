## 1. Goal

Let an authenticated doctor maintain the prescribed medication lines of a medical visit they own:

- add a medication line to an existing visit;
- update the mutable fields of an existing medication line;
- delete a medication line entered by mistake;
- read the medication lines back as part of the visit response.

Authorization, validation and error behaviour must match the existing visit/diagnosis slice exactly.

## 5. API contract

Base route: `/api/medical-visits`. All endpoints require an authenticated **Doctor** (D-16, D-18).

| # | Method | Route | Body | Success | Error codes |
|---|---|---|---|---|---|
| 1 | `POST` | `/api/medical-visits/{visitId:guid}/medications` | `CreateMedicationRequest` | `201` + `Location` (parent visit) + `MedicationResponse` | 400, 401, 403, 404 |
| 2 | `PUT` | `/api/medical-visits/{visitId:guid}/medications/{medicationId:guid}` | `UpdateMedicationRequest` | `200` `MedicationResponse` | 400, 401, 403, 404 |
| 3 | `DELETE` | `/api/medical-visits/{visitId:guid}/medications/{medicationId:guid}` | — | `204 No Content` | 401, 403, 404 |

**Deliberately absent:** a medication list route and any pagination contract (Q-04).

### 5.1 Requests

```text
CreateMedicationRequest
  string  MedicationName   required, trimmed, ≤ 200
  string  Dosage           required, trimmed, ≤ 100
  string  Frequency        required, trimmed, ≤ 100
  string? Duration         optional, ≤ 100, whitespace → null
  string? Instructions     optional, ≤ 4000, whitespace → null

UpdateMedicationRequest      // same shape; all mutable fields
  string  MedicationName
  string  Dosage
  string  Frequency
  string? Duration
  string? Instructions
```

Visit, patient and doctor identifiers are never accepted from the client; they come from the route
and the persisted visit.

### 5.2 Responses

```text
MedicationResponse
  Guid    Id, VisitId, PatientId
  string  MedicationName, Dosage, Frequency
  string? Duration, Instructions

MedicalVisitResponse
  … unchanged …
  IReadOnlyList<DiagnosisResponse>  Diagnoses
  IReadOnlyList<MedicationResponse> Medications   // new, D-24
```

Medications are ordered by `MedicationName`, then `Id` as a stable tie-breaker. No EF entity,
navigation property, doctor/patient contact data or password hash is returned.

### 5.3 Status codes and errors

Reuses the existing `ProblemDetails` mapping (D-10). `DELETE` returns `204` with an empty body.

| Status | When |
|---|---|
| `201` | Medication created; `Location` points at the parent visit (D-20) |
| `200` | Medication updated |
| `204` | Medication deleted |
| `400` | Request-shape validation failure |
| `401` | Missing/invalid token |
| `403` | Authenticated non-doctor |
| `404` | Visit or medication not found / not owned by the acting doctor |

## 7. Validation rules

`CreateMedicationRequestValidator` and `UpdateMedicationRequestValidator` (identical rules):

| Rule | Severity |
|---|---|
| `MedicationName` required, trimmed, ≤ 200 | error |
| `Dosage` required, trimmed, ≤ 100 | error |
| `Frequency` required, trimmed, ≤ 100 | error |
| `Duration` ≤ 100 | error |
| `Instructions` ≤ 4000 | error |

Whitespace normalization happens in the mapping profile via `MedicalRecordText.Normalize`, exactly
as for the visit text fields. Identifiers are not part of the requests, so no identifier rule is
needed in the validators.

## 8. Authorization and data scoping

| Rule | Implementation point |
|---|---|
| Only a `Doctor` may call the routes | `[Authorize(Roles = Roles.Doctor)]` on the controller |
| Acting doctor id comes from the authenticated principal | `RequireActingDoctorId()` in the service |
| A doctor may only touch a medication of a visit they own | Query filters `Visit.DoctorId == doctorId` (and `VisitId == visitId` for update/delete) |
| Out-of-scope records return `404` | `NotFoundException`, never a 403 that reveals existence |
| Secretary has no access | Doctor-only policy + test |

---

## 9. Persistence rules

1. `SaveChangesAsync(ct)` only.
2. `AsNoTracking()` on the visit read used by `GET`.
3. `Include(v => v.Medications)` wherever the response maps a visit.
4. Deterministic medication ordering before projection.
5. Never assign `VisitId`/`PatientId`/`Id` from client input.
6. Delete only the medication row; never cascade to the visit or the patient.
7. No migration and no Domain change.

---

## 10. AutoMapper rules

| Map | Direction | Notes |
|---|---|---|
| `CreateMedicationRequest → Medication` | input → new entity | Ignore `Id`, `VisitId`, `PatientId`, `Visit`, `Patient`; trim required strings; normalize optional strings |
| `UpdateMedicationRequest → Medication` | input → tracked entity | Same ignores; only the five mutable fields are written |
| `Medication → MedicationResponse` | entity → DTO | Explicit member map |
| `MedicalVisit → MedicalVisitResponse` | entity → DTO | `Medications` ordered by name then id (D-24) |

Forbidden: any convention-based mapping that copies identifiers or navigations from the request,
and any map that lets the client change `VisitId`/`PatientId`.
