## 4. Design

### 4.1 Endpoints

| # | Method | Route | Success | Notes |
|---|--------|-------|---------|-------|
| 1 | `GET` | `/api/patients/{patientId:guid}/medical-profile` | `200 OK` with `PatientMedicalProfileResponse` | Includes `bloodType`, `emergencyContact`, derived `age`, allergies, chronic conditions |
| 2 | `GET` | `/api/patients/{patientId:guid}/medical-visits?pageNumber=&pageSize=` | `200 OK` with `PagedResult<MedicalVisitResponse>` | Q-04 envelope; newest first (`VisitDate` desc, id tie-break); children per visit as in F3-C1 |

### 4.2 Controller behavior (thin adapter — AGENTS §4.1)

- `[ApiController]`, `[Route("api/patients/{patientId:guid}")]`, `[Authorize(Roles = Roles.Doctor)]`.
- Actions bind `patientId` from the route, `(GetMedicalHistoryRequest)` via `[FromQuery]`, then call the service and wrap in `Ok(...)`. **No validation, no query, no ownership logic in the controller** — the service already enforces the full authorization order and `403` happens before any data access.
- `ProducesResponseType` metadata per the F4 controller pattern (200/400/401/403/404).
- No changes to `Program.cs` (auth + `ICurrentUser` + DI registration all exist), no changes to F4's controller.

### 4.3 Error contract (produced by the shared handler, verified against the service)

| Situation | Status | `code` |
|---|---|---|
| No/invalid credentials | `401` | — (framework challenge, envelope via `UseStatusCodePages`) |
| Authenticated non-doctor (e.g. secretary) | `403` | `medical.access_denied` |
| Doctor identity unusable (missing/inactive) | `403` | `identity.invalid` |
| Unknown patient, NULL owner, another doctor's patient | `404` | `patient.not_found` (identical for all three) |
| `pageNumber < 1`, `pageSize` outside `1..50` | `400` | field errors via `errors`/`errorCodes` |

## 6. Test plan (`MedicalRecordsApiTests`, Arrange–Act–Assert)

Seeded data per test: one doctor + one secretary, patient owned by doctor A, a second doctor B,
visits with diagnoses/medications/vitals/notes/labs (reuse the seeding shapes from
`MedicalVisitsApiTests` / F3-C1 fakes).

1. **Authorized doctor access (profile):** doctor A → `200`, full profile, `bloodType`/`emergencyContact` present in the camelCase JSON, allergies/conditions ordered.
2. **Authorized doctor access (history):** doctor A → `200` paged envelope: correct `page`/`pageSize`/`totalCount`/`totalPages`, visits newest first, children present; `pageNumber` beyond the last page → `200` with empty `items` (CONVENTIONS.md rule).
3. **Secretary forbidden:** secretary (even one attached to doctor A's patients) → `403`, `code = medical.access_denied`, and **no medical data in the response** (AGENTS §7 API-level case #1).
4. **Cross-doctor denied:** doctor B on doctor A's patient → `404`, `code = patient.not_found` (AGENTS §7 API-level case #2).
5. **Unauthenticated:** no `X-Test-UserId` → `401` in the shared envelope.
6. **Invalid pagination:** `pageNumber=0` → `400`; `pageSize=51` → `400`; both carry `errors`/`errorCodes`.
7. **Nonexistent patient** for an authorized doctor → `404` `patient.not_found` (same shape as case 4 — no probing).
