# F10-C1 — Patient Medical Profile & Timeline: Backend

- Feature: F10   - Owner: Merihan   - Branch: `feature/merihan-medical-profile`   - Phase: Phase 2
- Status: Approved
- Depends on: F6-C1 checkpoint A; F9-C1 for vital-sign events (add that source after F9-C1 is merged); Phase 1 F3/F4 entities

## Goal
A paged, filterable, chronological timeline of a patient's real medical events, available only to the doctor who owns the patient.

## Source requirements
FR-11, FR-15, FR-18, FR-20, FR-27, FR-36, FR-37, FR-38; BR-04, BR-13, BR-16; BRULE-03, BRULE-04, BRULE-10; NFR-06, NFR-07 (response time, optimized queries). Event types per Q-20.

## Business rules & security constraints
Owner doctor only; secretary never; patient resolved from the route and checked against the token; most recent first by default (FR-37) with a stable tie-breaker; pagination applied in the data source over the combined events (no loading all events into memory); event DTOs carry a type discriminator and only the fields needed for display.

## Affected layers & files
Application: timeline service, event DTOs, query/filter object, validators, mapping profile. Infrastructure: efficient projection/union of sources + indexes on patient/date columns. Api: timeline action under patients (or the existing medical-profile controller).

## API contract (proposed)
`GET /api/patients/{patientId}/timeline?eventType=&from=&to=&page=&pageSize=` → paged list of events `{ id, type, occurredAt, title, summary, relatedVisitId? }` (shared pagination contract). `GET /api/patients/{patientId}/timeline/{eventType}/{eventId}` for event detail (FR-38) *(optional; may reuse existing detail endpoints)*.
