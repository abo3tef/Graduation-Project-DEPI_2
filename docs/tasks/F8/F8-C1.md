# F8-C1 — Patient Management & Search: Backend

- Feature: F8   - Owner: Menna   - Branch: `feature/menna-patients`   - Phase: Phase 2
- Status: Approved
- Depends on: F6-C1 checkpoint A (roles), Phase 1 patient entity

## Goal
Full patient CRUD with search and pagination, plus a lightweight lookup that powers a patient picker.

## Source requirements
FR-08, FR-09, FR-10, FR-12, FR-13, FR-40, FR-41, FR-49; BR-02, BR-03; BRULE-02, BRULE-03, BRULE-04, BRULE-10. Patient `DELETE` is not in the SRS: Phase 2 team scope + rule Q-17.

## Business rules & security constraints
Doctor: own patients only (patient belongs to the creating doctor's workspace). Secretary: only patients of assigned doctors, only basic fields (FR-49: name, DOB, gender, phone, address, emergency contact) — no blood type or medical data (Q-18). Owner doctor id comes from the token, never from the request body. Delete never cascades over medical/financial history (AGENTS §4.3); default rule Q-17: reject with 409 when the patient has appointments, visits, or payments. Validate DOB (not in the future), phone format, required fields.

## Affected layers & files
Domain: patient entity methods (create/update), configuration check. Application: patient service, DTOs (separate doctor and secretary DTOs), validators, mapping profile (explicit, no ownership fields mapped from input). Infrastructure: configuration/indexes for name/phone search. Api: patients controller.

## API contract
`POST /api/patients` · `GET /api/patients` (search by name/id/phone, filters, pagination, stable sort) · `GET /api/patients/{id}` · `PUT /api/patients/{id}` · `DELETE /api/patients/{id}` · `GET /api/patients/lookup?search=` *(proposed: small paged result id + fullName + phone for the picker)*. Pagination/filter contract = existing Phase 1 shared contract.

## Acceptance criteria
- [ ] Doctor creates/edits/lists/searches only own patients; another doctor's patient → 403/404.
- [ ] Secretary works only with assigned doctors' patients and never receives or sets medical fields.
- [ ] Search by name, id, phone works with pagination metadata and stable order.
- [ ] Delete of a patient with related records is rejected; empty patient is deleted.

## Common rules for this Cycle (AGENTS.md is authoritative)
- Pattern: MVC Controller (thin) → plain Application service → `IApplicationDbContext`; no MediatR, no extra repository. EF Core Code First; one `IEntityTypeConfiguration<T>` per persisted entity; migration reviewed and merged in the order set in STATE.md §4.
- FluentValidation for every request; AutoMapper profile for DTO mapping; never expose entities; reuse the existing Phase 1 pagination/filter contract (do not create another).
- Role and ownership come from the validated JWT, never from client input; secretary never reaches medical data.
