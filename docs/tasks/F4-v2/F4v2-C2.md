# F4v2-C2 — Diagnosis Delete: Frontend & Integration

- Feature: F4-v2   - Owner: Shalaby   - Branch: `feature/shalaby-auth`   - Phase: Phase 2
- Status: Approved
- Depends on: F4v2-C1, F6-C2 (central token)

## Goal
The doctor sees a delete action on each diagnosis in the visit screen, confirms it, and the list updates.

## Source requirements
FR-17, FR-18; D-23; NFR-10/11 (usability).

## Business rules & security constraints
Show the action only to doctors on their own visits (UX only); confirm dialog because the delete is permanent; show clear errors for 403/404.

## Affected layers & files
`features/visits` (or the existing medical-visit feature): api function, mutation hook, button + confirm dialog, cache invalidation; `messages/ar.json`, `en.json`. Coordinate with the owner of the visit screen files.

## API contract
As in F4v2-C1.

## Acceptance criteria
- [ ] Owner doctor deletes a diagnosis after confirmation and the list refreshes without reload.
- [ ] Cancel in the dialog changes nothing; errors are shown, not swallowed.
