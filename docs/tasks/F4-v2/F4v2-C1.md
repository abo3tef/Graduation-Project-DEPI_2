# F4v2-C1 — Diagnosis Delete: Backend

- Feature: F4-v2   - Owner: Shalaby   - Branch: `feature/shalaby-auth`   - Phase: Phase 2
- Status: Approved
- Depends on: Phase 1 F4 (diagnoses and visits exist); F6-C1 checkpoint A for role-protected testing

## Goal
The owning doctor can permanently delete a diagnosis they entered by mistake.

## Source requirements
FR-17, FR-18 (diagnosis management); BRULE-05, BRULE-06, BRULE-08 (doctor-controlled data); decision **D-23** (hard delete for correction by the owning doctor).

## Business rules & security constraints
Only the doctor who owns the visit/patient may delete; another doctor → 403/404 (follow the Phase 1 convention); secretary → 403; the diagnosis must belong to the visit in the route (otherwise 404); hard delete limited to this entity; no cascade to other medical data.

## Affected layers & files
Application: delete method on the existing diagnosis/visit service. Infrastructure: verify delete behavior in the existing entity configuration. Api: new action on the existing medical-visits controller.

## API contract
`DELETE /api/medical-visits/{visitId}/diagnoses/{diagnosisId}` → 204; 401; 403; 404 (visit or diagnosis not found / not matching).
