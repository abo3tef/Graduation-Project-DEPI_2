# F9-C2 — Vital Signs: Frontend & Integration

- Feature: F9   - Owner: Anton   - Branch: `feature/anton-vitals`   - Phase: Phase 2
- Status: Approved
- Depends on: F9-C1, F6-C2

## Goal
The visit screen lets the doctor add and edit vital signs and shows them with the visit.

## Source requirements
FR-26, FR-27; BR-09; NFR-10/11; AGENTS.md §6.5.

## Business rules & security constraints
Form fields and ranges mirror the backend rules (UX only); only the owning doctor sees edit controls; units displayed (bpm, °C, kg, cm, %, breaths/min).

## Affected layers & files
`features/visits` (vital-signs section, hook, api function, types), edits to the visit screen to host the section (coordinate with the visit-screen owner), `messages/ar.json` + `en.json`.

## API contract
As frozen in F9-C1.

## Tasks
- [ ] F9-C2-T1 Inspect the visit screen and DTO types.
- [ ] F9-C2-T2 API functions + TanStack Query hooks (list, create, update; invalidate visit).
- [ ] F9-C2-T3 Vital-signs form (add/edit) with validation messages and units.
- [ ] F9-C2-T4 Display vitals in the visit screen (latest + history for the visit).
- [ ] F9-C2-T5 ar/en messages; RTL check; loading/empty/error states.

## Acceptance criteria
- [ ] Doctor adds vitals during a visit and sees them immediately; edit works.
- [ ] Invalid values show clear messages; backend errors are surfaced.
- [ ] Secretary cannot reach vitals UI or data.

## Common rules for this Cycle (AGENTS.md is authoritative)
- Existing structure only (`app`, `components`, `features`, `data`, `i18n`, `messages`, `types`); feature code in `features/<name>/` with a barrel `index.ts`; no `src/`.
- Native `fetch` through the single shared API client + TanStack Query (queries/mutations, cache invalidation); no Axios; no new libraries without approval.
- Strict TypeScript, no `any`; loading / empty / error / success states; accessible forms; all text via next-intl with matching keys in `messages/ar.json` and `messages/en.json`; RTL/LTR safe layout.
- Frontend guards are UX only; the backend remains the enforcement point.
- Checks to run and report: `cd Front_End && npm run lint && npm run build`, plus a manual test with the seeded `Admin`, `Doctor`, `Secretary` users.
- Done = AGENTS.md §11 + Execution Report (`docs/reports/<CycleId>.md`) + proposed STATE.md update.
