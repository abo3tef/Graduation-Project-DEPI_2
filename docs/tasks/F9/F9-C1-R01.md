# F9-C1-R01 Plan — Vital-signs GET list must use the Q-04 paging contract

- **Date:** 2026-11-17
- **Type:** Review remediation plan for F9-C1 finding **R-01** (`docs/reports/F9-C1.md`)
- **Status:** **Approved 2026-11-17 · implemented and verified 2026-11-17.**
- **Owner:** Anton (F9) · shared contract owner: Tech Lead
- **Scope:** one bounded backend change to the already-approved F9-C1 GET route only.

## 1. Problem

`GET /api/medical-visits/{visitId}/vital-signs` currently returns an unbounded JSON array
(`IReadOnlyList<VitalSignsResponse>`):

- `backend/src/Medilog.WebAPI/Controllers/MedicalVisitsController.cs:224`
- `backend/src/Medilog.Application/Features/MedicalRecords/MedicalVisitService.cs:317-337`

This conflicts with:

- `docs/tasks/F9/F9-C1.md:50` — “reuse the existing Phase 1 pagination/filter contract”;
- `AGENTS.md` §3.1 — list endpoints must be filtered/paged at the data source, validate inputs,
  use deterministic ordering and have a bounded page size;
- `backend/docs/api/CONVENTIONS.md` §3 — every list endpoint uses the Q-04 page envelope.

No database or domain change is needed. No new list endpoint is introduced; the F9-C1 task file
already approves this route.

## 2. Applicable constraints

### Functional requirements
- FR-26/FR-27 — record and edit vital signs linked to a medical visit (F9-C1).
- F9-C1 API contract — `GET /api/medical-visits/{visitId}/vital-signs` must exist.
- Q-04 / `CONVENTIONS.md` — `pageNumber` (default 1, ≥ 1), `pageSize` (default 10, 1…50),
  response `{ items, page, pageSize, totalCount, totalPages }`.

### Business rules / security
- BRULE-05 / BRULE-10 — only the owning doctor may read; secretary is forbidden.
- BRULE-04 / AGENTS §5 — the route visit and the persisted `DoctorId` decide scope; never accept a
  patient or doctor id from query or body.
- Q-19 — append semantics, no delete, no change to measurement rules or ranges.

### Non-functional requirements
- Count and page fetch must happen in EF Core (data source), never by materialising all records.
- Deterministic ordering: `Id ASC`; `VitalSigns` has no `CreatedAtUtc`, so `Id` is the sole
  stable key (already documented in `MEDICAL_RECORDS_API.md` §4.4).
- Invalid page values return `400` through the shared `ProblemDetails` envelope with
  `code = validation.failed` and camelCase field errors.
- No unbounded `pageSize`; use only `PagingDefaults` (`MinPageNumber = 1`, `DefaultPageNumber = 1`,
  `DefaultPageSize = 10`, `MaxPageSize = 50`).
- No new NuGet package, no MediatR/CQRS, no extra repository, no EF changes.

## 3. Proposed change (one Cycle)

### 3.1 API contract

```http
GET /api/medical-visits/{visitId}/vital-signs?pageNumber=1&pageSize=10
```

Response `200 OK`:

```json
{
  "items": [
    {
      "id": "d3e4f5a6-b7c8-4d9e-0f1a-2b3c4d5e6f70",
      "bloodPressure": "120/80",
      "heartRate": 72,
      "temperature": 36.8,
      "respiratoryRate": 16,
      "weight": 70.5,
      "height": 175.0,
      "spO2": 98
    }
  ],
  "page": 1,
  "pageSize": 10,
  "totalCount": 1,
  "totalPages": 1
}
```

Rules:

- `pageNumber < 1` or `pageSize < 1` or `pageSize > 50` → `400 validation.failed`.
- A page beyond the last returns `items: []` with correct `totalCount` and `totalPages`.
- No filters are added in this Cycle. The entity has no timestamp for a meaningful range filter
  and Q-19 did not approve one.
- The `POST` `Location` header remains this GET list route.

## 5. Acceptance criteria

1. `GET …/vital-signs` returns `200` with `{ items, page, pageSize, totalCount, totalPages }`.
2. Omitted paging parameters behave as `pageNumber=1`, `pageSize=10`.
3. `pageNumber=0`, `pageSize=0`, `pageSize=51` (and non-integer values) return `400` with
   `code = validation.failed` and camelCase field errors.
4. `totalCount` and `totalPages` are correct; a page past the last returns empty `items`.
5. Records are returned in `Id ASC` order across pages with no duplicates or omissions.
6. Doctor ownership, secretary `403`, anonymous `401`, foreign visit `404`, append, PUT, no-delete
   and client-body-id isolation behavior remain unchanged.
7. `dotnet restore`, `dotnet build Medilog.sln`, `dotnet test Medilog.sln` all pass with the raw
   workspace configuration.
8. No new list contract, no new package, no EF model change.
