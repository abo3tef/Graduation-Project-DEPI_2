# F6-C2 — Authentication & Identity: Frontend & Integration

- Feature: F6   - Owner: Shalaby   - Branch: `feature/shalaby-auth`   - Phase: Phase 2
- Status: Approved
- Depends on: F6-C1 (at least checkpoint A + register + verify + reset + google endpoints agreed)

## Goal
Users can register, verify email, log in (password or Google), recover their password, and every API call uses one central token; the dev token panel is gone.

## Source requirements
FR-01, FR-02, FR-03 (logout), FR-04, FR-05; NFR-10, NFR-11; Phase 2 team decision (verification, Google). Localization requirement: AGENTS.md §6.5.

## Business rules & security constraints
Frontend guards and role-based redirects are UX only; token handling per the approved decision (Q-13); no token in URLs or logs; verification/reset tokens come from the email link and are sent to the API once; generic messages for forgot-password; Firebase config only as public `NEXT_PUBLIC_*` values.

## Affected layers & files
`features/auth/` (api, components, hooks, types, `index.ts`), `app/[locale]/(auth)/login|register|verify-email|forgot-password|reset-password`, shared API client in `data/` (single place that attaches the token and handles 401), route protection/redirects, `messages/ar.json` + `en.json`, removal of `DevTokenPanel` and dev-token code.

## API / data contract
As frozen in F6-C1. Frontend types mirror the DTOs.

## Common rules for this Cycle (AGENTS.md is authoritative)
- Existing structure only (`app`, `components`, `features`, `data`, `i18n`, `messages`, `types`); feature code in `features/<name>/` with a barrel `index.ts`; no `src/`.
- Native `fetch` through the single shared API client + TanStack Query (queries/mutations, cache invalidation); no Axios; no new libraries without approval.
- Strict TypeScript, no `any`; loading / empty / error / success states; accessible forms; all text via next-intl with matching keys in `messages/ar.json` and `messages/en.json`; RTL/LTR safe layout.
- Frontend guards are UX only; the backend remains the enforcement point.
- Checks to run and report: `cd Front_End && npm run lint && npm run build`, plus a manual test with the seeded `Admin`, `Doctor`, `Secretary` users.
- Done = AGENTS.md §11 + Execution Report (`docs/reports/<CycleId>.md`) + proposed STATE.md update.
