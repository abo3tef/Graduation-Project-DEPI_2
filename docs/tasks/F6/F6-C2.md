# F6-C2 — Authentication & Identity: Frontend & Integration

- Feature: F6   - Owner: Shalaby   - Branch: `feature/shalaby-auth`   - Phase: Phase 2
- Status: In review
- Depends on: F6-C1 (at least checkpoint A + register + verify + reset + google endpoints agreed)

## Goal
Users can register, verify email, log in (password or Google), recover their password, and every API call uses one central token; the dev token panel is gone.

## Source requirements
FR-01, FR-02, FR-03 (logout), FR-04, FR-05; NFR-10, NFR-11; Phase 2 team decision (verification, Google). Localization requirement: AGENTS.md §6.5.

## Business rules & security constraints
Frontend guards and role-based redirects are UX only; token handling per the approved decision (Q-13); no token in URLs or logs; verification/reset tokens come from the email link and are sent to the API once; generic messages for forgot-password; Firebase config only as public `NEXT_PUBLIC_*` values.

## Affected layers & files
`features/auth/` (api, components, guards, hooks, routing, session, types, `index.ts`), `app/[locale]/(auth)/login|register|verify-email|forgot-password|reset-password`, the existing shared API client in `lib/api/` (single place that attaches the token and handles 401), route protection/redirects, `messages/ar.json` + `en.json`, removal of `DevTokenPanel` and dev-token code.

## API / data contract
As frozen in F6-C1. Frontend types mirror the DTOs.

## Approved plan (build order)
Approved by the owner before implementation; executed one slice at a time, each slice gated by
`npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`.

Approved decisions:
- **D-C2-1** — Admin lands on `/` with a signed-in notice; admin screens wait for F11.
- **D-C2-2** — `/payments` stays unguarded; it is F7's screen.
- **D-C2-3** — `SessionBadge` replaces `DevIdentityChip` in the header, the appointments app bar and the doctor dashboard.
- **D-C2-4** — medical-records mutations require a signed-in Doctor.
- **Q-13** — one `localStorage` key (`medilog-auth-session`) plus an in-memory copy; the token is read in exactly one place (`registerSessionAuth`) and sent as `Authorization: Bearer <token>`; any `401` clears the session and redirects to `/login?reason=expired`; no refresh-token flow.

Slices:
1. **E1 — session core**: `session/session-store.ts` (single credential owner, expiry skew, corrupt/expired records removed on read), `session/session-auth.ts` (bearer provider + 401 handler), `lib/api/unauthorized-handler.ts` registry, `useSession`/`useActingIdentity`/`useSignOut`, `routing/landing.ts`, `guards/RequireRole.tsx`, `SessionBadge`, `SessionExpiryWatcher`; dev identity removed.
2. **E2 — auth data layer**: `api/auth.api.ts`, `types/auth.types.ts`, `validation/auth.validation.ts`, `errors/authErrorMessageKey.ts`, `hooks/useAuthMutations.ts` + unit tests.
3. **E3 — screens & routing**: the five auth pages and forms, post-login redirects, `RequireRole` on the protected layouts/pages.
4. **E4 — Google**: `firebase` dependency, `google/firebase-client.ts`, `GoogleSignInButton`, `POST /api/auth/google`; absent config renders a "not configured" message.
5. **E5 — cleanup**: remove `use-dev-token.ts`, `DevTokenPanel`, `ApiRequestOptions.token` and the token threading in medical-records.
6. **E6 — report & state**: execution report, task checkboxes, `STATE.md`.

## Common rules for this Cycle (AGENTS.md is authoritative)
- Existing structure only (`app`, `components`, `features`, `data`, `i18n`, `messages`, `types`); feature code in `features/<name>/` with a barrel `index.ts`; no `src/`.
- Native `fetch` through the single shared API client + TanStack Query (queries/mutations, cache invalidation); no Axios; no new libraries without approval.
- Strict TypeScript, no `any`; loading / empty / error / success states; accessible forms; all text via next-intl with matching keys in `messages/ar.json` and `messages/en.json`; RTL/LTR safe layout.
- Frontend guards are UX only; the backend remains the enforcement point.
- Checks to run and report: `cd frontend && npm run lint && npm run typecheck && npm run test && npm run build`, plus a manual test with the seeded `Admin`, `Doctor`, `Secretary` users.
- Done = AGENTS.md §11 + Execution Report (`docs/reports/<CycleId>.md`) + proposed STATE.md update.
